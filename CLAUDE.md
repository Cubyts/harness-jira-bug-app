## Golden Rules (Non-Negotiable)

**Scope**
1. Do what was asked — nothing more, nothing less.
2. Do not refactor unless explicitly requested.
3. Do not fix unrelated issues opportunistically.
4. If requirements are ambiguous or conflicting, output the specific question and STOP before implementing. Do not guess.

**Code style**
5. Follow existing code style over best practices.
6. Keep changes minimal and localized.
7. Do not break existing behavior.
8. Do not introduce new patterns, libraries, or dependencies without approval.

**Comments**
9. Comment only to explain WHY — never WHAT the code does.
10. Do not add docstrings or headers to existing functions unless asked.

**Error handling**
11. Do not add try/catch, validation, or fallbacks for cases that can't happen.
12. Validate at system boundaries only (user input, external APIs).

**Security**
13. Never commit secrets, API keys, or credentials in source — read from env / secret store.
14. In error responses, never expose stack traces, internal file paths, framework versions, library names, or database query text. Sanitise at the response boundary.

**Testing**
15. Run existing tests before claiming work complete.
16. Add tests for new behavior; do not modify existing tests to make them pass.
17. Do not modify unrelated production code to make a failing test pass. If a test exposes a real bug, fix the bug directly with a minimal change.

**Configuration**
18. When adding or renaming an environment variable, config property, or feature flag, document it in the canonical config example file (e.g. `.env.example`, `appsettings.json`) — create the file if missing.

**Destructive actions**
19. Confirm before deleting files, dropping schema, force-pushing, or modifying CI/CD.
